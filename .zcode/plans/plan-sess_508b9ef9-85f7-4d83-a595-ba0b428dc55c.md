# 最终方案：全部改动只在 CustomTraffic 插件内（核心/主题零改动）

## 问题1：换套餐时 renew-hint 显示错误 — 修复

原因：`/custom-traffic/last` 只查最近一条完成的 CustomTrafficOrder，不看用户当前套餐。换套餐后仍显示「一致（80G）→叠加天数」，而核心实际按换套餐处理（expired_at 重起算 + 剩余价值折抵）。

1. **插件后端 `Controllers/CustomTrafficController::last()`**：接受可选 `plan_id`；结合 `user->plan_id` 与订阅活跃状态（expired_at 为 null 或 > time()）返回 `context`：
   - `renew`（同套餐且活跃）→ 附带 `traffic_gb`
   - `plan_change`（在别的套餐且活跃）→ `traffic_gb: null`
   - `expired`（同套餐但已过期）→ `traffic_gb: null`
   - 无记录 → null（前端隐藏提示）
2. **插件前端 `resources/assets/custom-traffic.js`**：`updateRenewHint()` 三态文案：
   - renew 一致 → 绿（原文案）/ 不同 → 橙（原文案）
   - plan_change → 橙：「你当前订阅的是其他套餐，本次购买将更换套餐：剩余价值自动折抵，时长从购买时重新起算，不叠加天数」
   - expired → 橙：「当前订阅已过期，本次购买时长从购买时重新起算」
   - `loadLastPurchase()` 请求带 `?plan_id=`（从 hash 取，现有重拉逻辑复用）
3. `order.open.after` 续费钩子行为不动（核心对换套餐/新购本来就重置天数，问题纯在文案）。

## 问题2：重置包顺延制（A，永远顺延）

语义：买重置包 = 立即重置流量 + 下次自动重置日顺延一个月（预支下一次自动重置），任何时间购买价值恒定。

1. **`Plugin.php` 扩展现有 `order.open.after` 监听**：在 CustomTrafficOrder 早退之前处理 `$order->period === Plan::PERIOD_RESET_TRAFFIC` 的订单：`next_reset_at` 非空 → `addMonthNoOverflow()` 顺延一个月保存；受新插件配置 `reset_shift_enable`（默认开）控制。只改 next_reset_at 字段：不触发 UserObserver 重算（仅 plan_id/expired_at 变化才重算）、不触发节点同步。
   - 已知边界（写入插件 README）：顺延后若续费/换套餐导致 expired_at 变化，核心会按锚点重算 next_reset_at，顺延可能被覆盖。
2. **插件前端**：plan 详情页检测「选择付款周期」卡片含重置包选项（复用现有 PERIOD_KEY_MAP/findCardByTitle 机制）时，fetch 现有 `/user/getSubscribe`（只读，含 next_reset_at）注入提示：「下次自动重置：M月D日（还有 X 天）。购买重置包将立即重置流量，并将下次自动重置顺延一个月」；`guest_comm_config` 注入 `reset_shift_enable` 控制是否显示。
3. 插件购买页规则说明文案（TIP 卡片）同步补充顺延规则。
