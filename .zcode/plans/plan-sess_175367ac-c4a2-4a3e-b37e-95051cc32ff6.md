## 目标
将 `/custom-traffic/plan9` 改造成单页注册购买入口：用户选择流量和周期，填写邮箱、密码、邀请码，点击一次“立即购买”后复用核心注册逻辑创建账号和待支付订单，随后直接进入现有支付页面；支付成功后由核心支付回调开通套餐并进入仪表盘。同时修复价格区域同一次操作闪烁两次的问题。

## 已确认的约束
- 新注册账号百分百没有余额，因此不走余额抵扣或自动支付分支。
- 服务器不能伪造支付成功；必须调用现有启用的真实支付方式。
- 注册、邀请码、密码加密、订单、支付回调和套餐开通尽量复用项目已有代码。
- 旧的 `hold → SPA 注册 → 自动创建订单` 链路需要保留兼容，不能影响普通注册。

## 实施方案

### 1. 修复价格重复闪烁
修改 `plugins/CustomTraffic/resources/views/landing.blade.php`：
- 本地即时计算作为首次唯一渲染来源，首次从 `¥--` 填充时不播放价格过渡或价格框 pop 动画。
- 维护当前显示的 `traffic_gb/period/monthly_price/total_amount` 状态。
- `/public/quote` 仅在服务端返回金额与当前显示金额不一致时更新数字；金额一致时不改 DOM、不重新触发 pop。
- 继续使用 AbortController 和请求序号，旧请求不能覆盖最新选择。
- 滑块、数字输入、步进按钮和周期切换每次只触发一次本地视觉更新；网络报价只负责校准。
- quote 失败时保留最近一次有效价格并显示错误，不清空价格区域。

### 2. 在落地页增加注册表单
在购买卡中加入：
- 邮箱输入框；
- 密码输入框，前端至少校验 8 位；
- 邀请码输入框；
- 注册/支付状态提示。

点击购买前校验邮箱、密码、流量、周期，并防止重复提交。邀请码是否必填仍由后端 `invite_force` 最终判断，前端不写死站点规则。

### 3. 新增“注册并创建订单”插件接口
在 `plugins/CustomTraffic/routes/api.php` 增加公开接口，例如：

```text
POST /api/v1/custom-traffic/register-order
```

控制器实现原则：
- 使用现有 `AuthRegister` 请求校验和 `RegisterService::register()`，复用注册关闭、邮箱白名单、重复邮箱、注册频率、邮箱验证、邀请码和 `UserService::createUser()` 密码加密逻辑。
- 注册请求携带独立流程标记及当前选择 token；不把金额作为权威参数，不信任前端金额。
- 注册成功后使用 `AuthService::generateAuthData()` 生成 Bearer token。
- 使用 `Cache::pull()` 原子消费选择 token，再复用现有 CustomTraffic 订单创建逻辑，重新校验套餐、可售状态、流量范围、周期、月付门槛和未支付订单限制。
- 抽取或复用现有 `consumePending()` 的公共建单方法，避免新接口和旧注册钩子复制订单逻辑。
- 新接口创建订单时不依赖余额支付；订单保持待支付状态，返回 `trade_no`、`auth_data` 和必要的订单信息。
- 如果注册校验失败，不消费选择 token，允许用户修正表单后重试。
- 如果注册成功但建单失败，返回明确错误并记录日志；避免静默注册成功后用户找不到订单。对重复请求做幂等保护，不能重复创建订单。
- 通过明确的流程标记跳过旧 `user.register.after` 中对同一 token 的重复消费；普通 `plan_token` 注册流程继续使用原钩子。

### 4. 注册成功后直接进入支付页面
由于新账号没有余额，前端收到 `auth_data + trade_no` 后：
- 将 Bearer token 暂存在当前页面内存中，不写入 URL。
- 用该 token 请求已有 `/api/v1/user/order/getPaymentMethod`，读取启用的真实支付方式。
- 若没有可用支付方式，显示“暂时没有可用支付方式”，保留订单号和错误状态。
- 显示支付方式选择；若只有一种可用方式可自动选中，但仍调用真实 checkout。
- 调用现有 `/api/v1/user/order/checkout`，传入 `trade_no` 和 `method`，复用核心 `PaymentService::pay()` 返回的数据。
- 根据核心支付响应类型处理跳转：优先复用现有支付插件返回的 URL/HTML/二维码语义；不自行伪造支付页面。
- 支付回调返回后，通过订单状态接口轮询 `pending/processing/completed`；状态完成后跳转 `/#/dashboard`，取消或失败则留在支付状态区域并允许重试。
- 零元 checkout 分支不作为新账号主流程，但保留后端核心兼容行为。

### 5. 后端注册与订单边界
- 旧 `/hold`、`user.register.after`、`auto-order` 接口保留，现有 SPA 注册不回归。
- 新接口只允许消费当前访客页面生成的 Redis token；token 继续短 TTL、一次性消费。
- 注册成功后若支付失败，账号和待支付订单保留，用户可重新发起 checkout，不重复注册和建单。
- 真实支付成功后继续由核心 `OrderService::paid()`、`OrderHandleJob`、`OrderService::open()` 和 CustomTraffic `order.open.after` 钩子开通套餐并写入自定义流量。
- 不在新接口中直接修改用户套餐状态、不直接设置订单为已支付。

### 6. 版本与验证
- 插件版本从 `1.0.45` 升级到 `1.0.46`，同步 README 和数据库安装记录。
- 运行 PHP、Blade、内嵌 JavaScript 语法检查，`view:clear`、`octane:reload`、插件范围 `git diff --check` 和路由检查。
- 不提交真实账号或真实付款；验证注册失败可重试、邀请码错误、重复点击、无支付方式、旧报价响应丢弃和价格只更新一次。
- 浏览器后端恢复后验证：单页表单、注册成功、支付方式展示、跳转支付、支付回调状态轮询和完成后仪表盘跳转。

## 验收标准
- 同一次流量/周期选择只渲染一次价格，不再出现双重闪烁。
- 用户无需跳转注册页即可在 `/custom-traffic/plan9` 完成账号注册和订单创建。
- 新账号注册后直接进入真实支付页面，不依赖余额，也不伪造支付成功。
- 支付成功后套餐生效并跳转仪表盘；支付失败时账号和待支付订单可继续支付，且不会重复建单。
